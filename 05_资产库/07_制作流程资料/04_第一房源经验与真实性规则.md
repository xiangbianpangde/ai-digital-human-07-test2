# 第一房源经验、踩坑与可复用真实性规则

> 本文基于[真实生产恢复](03_第一房源真实生产过程.md)、原始用户反馈、已存在代码/原片和前轮实测证据。有效指“解决本案例具体问题”，不是证明营销转化、最佳脚本或跨房源成功。
> 25.30秒本片和约34秒参考片都不是60秒案例。下述60秒方法仅为未来设计建议，必须新案例实测。

## 2. 无效/被放弃的方法

| 方案/错误 | 为什么无效 | 保留什么与安全替代 |
|---|---|---|
| 先移动到点、再机械转向 | S1出现直面墙停留，观感割裂 | 保留失败反馈；试录耦合运动或硬切，不用加速掩盖看墙 |
| 门口只窥见主卧小角落 | 买家看不懂主卧核心，S4被退回 | 先明确主体与可见范围，再选择内部真实点位 |
| 主卧旋转越多越好 | 扫到无信息墙面、拉长节奏；用户要求角度收紧 | 只展示核心；“展示全貌”不是必须360°或每堵墙 |
| 卫浴朝洗手台直线推进 | 墙体遮挡浴缸；无卖点证据 | 真实可达的斜向/慢摇路线或固定点降级，验证后用 |
| 同一卧室重复三镜 | 新信息不足，用户质疑意义 | 删除冗余；转向尚未展示但真实可见的核心配置 |
| 平滑模型俯冲/穿顶 | 历史C04出现黑场与不可落地连续性 | 接受模型总览→硬切入室；标明“三维户型示意”，不冒称真实连续走入 |
| 过强推拉/长叠化 | P03/P05/P06原效果视觉拒绝，可能失真/叠影 | 仅用独立安全变体，不将父方法改为ready；保持几何和现实身份 |
| 原高速甩镜、碎裂、跨房间插帧 | P08原效果禁止；P09原碎裂未实现；P10几何证据与许可不足且用户暂不付费 | 真实原片剪辑；有服务不代表可修改房屋结构，低成本替代不冒充原效果 |
| 半透明说明遮罩漏底 | 首版在编码后仍可见不该漏出的内容 | 以编码后的完全遮挡检查为准；保留旧许可撤销，新02版与新ID独立审查 |
| 底栏/多层字幕自动“好看” | 用户退回字幕，要求参考片风格 | 当前重做黄白描边字；仍要文字事实、移动端可读性和完整口播字幕检查 |
| 为AI好看补数字与材质 | 12米、床尺寸/材质等不能从画面或标签求和自由推导 | 去掉无证据断言或补可靠来源；不改核心档案掩盖事实漂移 |
| 固定路径和沿用已有音轨 | `-y`覆盖、旧音轨可能与新台词不一致 | 将来参数化/新版本输出；本轮只阅读，不重跑TTS或合成 |
| 用“100%”与日志日期代替终审 | 原S6日期早于真实用户退回字幕，技术码率表也不准确 | 用户entry时间＋产物SHA＋具体审核范围；追加校正，不删除历史 |

没有可靠耗时/费用账，不能编造“省时80%”或“全部零成本”。原TTS真实生成与P10未付费是不同事项；未来按步骤记录调用次数、渲染耗时、人工轮次、直接成本与返工原因。

## 3. 已解决与仍未解决

**已解决的特定问题**：S1转向连贯性重构、S4核心主张/浴缸方向/重复镜头、S4人工批准、终片归S6、字幕包装重新实现、方法库单房源选择门禁。以对应反馈/文件为限。

**仍未解决或未验收**：裁切图旧哈希；12米等事实主张；原30–45秒/数字人要求与实际25.30秒不等价；S3音频超预算/时间轴差异；完整听音及最后字幕终审；权利与营销效果；桌面Computer Use；米级净空、原生高度授权证据细度；跨房源、数字人、方言。详见[扩库G00–G11](02_扩库清单与技能化边界.md)。

新增发现：真实用户反馈时间推翻旧S6事件日期；先全案写蓝图存在边写边测规则偏差；前轮“已完成”表述过宽。后续项目状态必须区分“视频文件已交付”和“人工业务收尾完成”。

## 4. 房屋真实性不可变规则（适用于以后所有房源）

| 规则ID | 必须执行 | 明确禁止 / 拒绝条件 |
|---|---|---|
| TR-01 身份 | 每个事实、画面、点位绑定房源ID及来源版本 | 将第一套资料/点位/装修/采光混入第二套 |
| TR-02 来源 | 原文件保留、哈希登记；URL有采集时间与房源匹配 | 来源缺失或哈希不符却手改索引放行；未知填0或编值 |
| TR-03 结构 | 户型、房间数量、门窗、阳台、空间关系以真实资料为准 | 图生视频/修图凭空添加、删除、扩大、穿墙连通或改变结构 |
| TR-04 面积 | 标称、产权、室内标签和、几何量测分别记录，单位与日期明确 | 把标签和认定产权套内、公摊、得房率或从图片比例推导精确米数 |
| TR-05 朝向/采光 | 页面朝向、指北针、可见日照分别绑定来源 | 不查方向就写南北通透、全天采光、无遮挡；单帧明亮证明全年采光 |
| TR-06 现状/装修 | 当前空置/家具/门窗/装饰可见现状如实描述 | 凭图认定材质品牌/装修年份或AI替换装修后称“现状实拍” |
| TR-07 图像处理 | 裁切、曝光、稳像限不改变结构；另存派生文件并说明 | 删除结构/缺点、虚构窗景、拉宽房间、隐去关键瑕疵；示意图冒充实景 |
| TR-08 周边 | 学校/交通/商业/医疗/景观以有效来源及距离口径为准 | 从宣传文字推保证入学、步行分钟、未来兑现或永久景观；学校名称不等于学区资格 |
| TR-09 价格/交易 | 指明总价/单价、币种单位、挂牌/成交类型、日期与来源 | 把旧报价当现价、挂牌当成交、主动议价空间/升值承诺；无价格就杜撰 |
| TR-10 用途建议 | “可考虑做书房”归生活建议，与原房间名称分开 | 改房间法定用途/卧室数，或把未完成布置说成既有配置 |
| TR-11 主张一致 | 普通话、方言、配音、字幕、卖点表均引用同一事实ID | 方言改写放大“约”、面积、价格、数量、朝向或服务承诺；字幕擅自新增12米 |
| TR-12 运镜 | 真实可达、显示点位/朝向/视场与实际画面；新房源单镜重测 | 复制旧yaw/轨迹保证安全；FOV称真实位移、模型飞行称真人走入 |
| TR-13 物理边界 | 真人1.5–1.6m，离墙/家具≥0.5m是目标；没有距离证据标未核证 | 全景伪平移伪造高度；把邻接可达或接触表接受当净空测量；例外跨房源继承 |
| TR-14 人物/声音 | 真实中介姓名/身份/形象/声音与授权核对；合成身份明示 | 克隆无授权真人、伪称中介实录；普通话TTS等同数字人或武汉方言能力 |
| TR-15 权利 | 原片、模型、音乐、字体、声线、形象与平台录制许可分别查 | 内部研究可见等同可商用；公开URL等同允许下载或再发布 |
| TR-16 审核/版本 | 分技术、视觉、事实、权利、人类批准；签认具体SHA及范围 | 实现者自称PASS充当最终业务批准；部分批准当全片接受，最新版无版本绑定 |
| TR-17 成本/工具 | 新服务/模型/付费/账户操作先明确范围和预算，凭证本机隐藏输入 | 聊天/库里存Key；为炫技调用高成本模型；安装工具等于采集/制作授权 |
| TR-18 不可静默纠错 | 日志纯追加；旧片旧稿保留，修改用新版本/新take | 改旧哈希、回填复选框、覆盖原文件或重排日期让历史看起来全部正确 |

核心原则：**真实性＞自动化程度；流程稳定性＞单次速度；真实案例验证＞理论Skill设计。**没有来源或可能改变事实的动作默认停止；人可以选择删去主张或补证，不能用审核“批准”让假房屋事实成立。

## 5. 人工审核绝不能被自动化替代

- 用户/经纪人确认房源身份、当前价格/交易口径及可披露内容；产权/学校/权利材料需要相应权威来源。
- 业务方确认定位、目标受众假设、主卖点排序和是否接受需求偏差。
- 每镜审看真实可见主体、空间连贯、舒服程度与遮挡；受限房间降级优于伪造空间。
- 本地表达者审方言自然度、礼貌及中介身份；权利人确认声音/形象可用。
- 终审按当前成片版本完整看片/听音，再确认字幕事实、权利及发布许可；AI只能提出检查结果，不自我签认。

## 6. 60秒信息密度与人物/3D节点：仅作待验证建议

60秒不是硬性目标：先写事实主张数，再以实测语音时长预算，每一镜只留一个主结论＋一个证据；宁可减主张，也不靠无限提速。以`可用镜长－实测语音长度－实际转场占用`检查留白；任何负值必须改短文案/延长获准镜头/换定位，不能凭平均字数宣布舒适。

3D模型适合在需要解释户型关系时短时总览并明确示意，随后回到真实空间证据；模型与房间内路径都要单项验证。高斯泼溅只有第二案例现有素材与实际能力支持时才考虑，不能为了工具名称硬加。

真人中介若确有身份/肖像/声线授权，可在开头建立身份、重要判断节点和结尾CTA短时出现；这只是备选，不代表“最适合节点”已被本片证明。数字人另行验证口型、遮挡、身份标识和成本，默认不加入第二套试片。

## 7. 本轮原子复盘

**经验R-01：恢复真实流程时，原始用户审核时间比助手撰写的“交付日期”更可靠。**同一事件要绑定反馈entry、产物SHA和审核范围；日志日期冲突通过CORRECTION留痕，不删旧历史。此规则在后续每个房源、每次Skill测试都适用。

**经验R-02：先证明一项房源能力，再封装一次重复动作。**两套房源之前只收集输入/输出/失败/门禁证据，不制造“自动全流程已完成”的Skill承诺。
