## 2. 每条新增资料的最小记录

尽量复用现有`source_manifest.json`与`方法库.json`字段，不先创建另一套竞争索引。以下是资料采集清单，不是新机器合同。

| 字段组 | 至少记录 |
|---|---|
| 身份 | 资产ID / 方法ID / 房源与场景 / 新take ID / 记录时间 |
| 来源 | 原文件或URL、源类型、来源日期、SHA-256；网页截图要能追溯到房源 |
| 内容与事实 | 解决什么问题；事实/推断/示意分类；主张对应的核心档案字段或可见证据 |
| 条件与参数 | 工具版本、页面/SDK前提、真实点位、yaw/pitch单位、FOV、时长、输入素材 |
| 执行与验收 | 执行器、原片、遥测、技术check、实际看过的接触表/短转场逐帧表、视觉review |
| 许可与边界 | 用户批准的具体范围；公开使用权；本房源限定；高度例外和净空未核证 |
| 失败与降级 | 不可达、贴图未到、看墙停顿、叠影、事实漂移的停止条件；安全替代不能冒充原效果 |

新增素材先登记再用于设计/生产；原图、原片、旧take和review不覆盖。新方法应遵守“一项资料 → 一项实测 → 一次审核”，而不是先堆一整套未测方法。

## 3. 面向最终skills的候选职责

这些是便于收集资料的职责划分，**不是已经定稿或实现的技能包**：

| 候选职责 | 现有基础 | 仍需证明的能力 |
|---|---|---|
| 贝壳户型图获取 | 截图结果、VR源、永久资产台账 | 房源匹配、可重放页面操作、原图归档、失败/登录分支；G02优先 |
| 房产事实整理 | 核心档案、JSON、面积求和与口径纪律 | 换房源后的信息提取、未知字段处理、文案事实绑定 |
| 单镜设计与漫游验证 | 已测方法、SDK点位、23项门禁测试、生产镜头经验 | 新房源能力探测、单镜授权/版本记录、Computer Use与SDK独立降级 |
| 成片整编与验收 | 五镜素材、TTS清单、双色字幕、25.30秒终片 | 防覆盖输出、真实时间轴、听音/视觉审核、需求偏差与权利检查 |

已经可用的浏览器工具、ffmpeg和现有单项执行器应优先复用。本机已有`beike-buy`（房源检索/详情）与`mmx-cli`（媒体服务）技能是后续集成候选，**本轮未验证它们能自动取得本户型图或完成数字人链路**。真正开始编写Pi skill前，再读取skill-authoring规范、检索现有pi-package并明确触发/输入/权限/停止条件；本轮不新增`SKILL.md`、Pi扩展或工具。

## 4. 建议下一次只做一件事

**优先补G02：贝壳户型图获取的最小可重放操作记录。**这是用户明确希望固化的环节，也是当前“有结果、无操作证据”的最大断层；其他扩库事项按授权逐项推进。

G00是素材复用前必须处理的旧台账问题，原始截图可作为核对起点；本轮不覆盖裁切图或旧哈希。可并行进行的仅是既有资料只读核对；不要把本清单解释成自动开始G01重剪、G03桌面修复、G08全屋试拍或G11新房源实验。

## 5. 本轮复盘

**可复用判断：完成状态按“具体产物＋事件时间＋对应授权”判定，而不是按目录名称、旧交接赞誉或LOG物理末行。**本例17:55批准、18:15完成、18:30交付晚于文件末段16:30/17:00待审记录；保留历史，校正入口，避免重复待审或擅自推进。

另一条边界：技术解码、视觉采样、几何净空、人工批准是四种不同证据，不能相互代替。已完成本片与具备跨房源可重放skills，是两个不同的完成条件。
