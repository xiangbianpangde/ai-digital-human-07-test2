# 统一方法库执行与取舍

## 边界

统一机器索引位于 `05_资产库/06_房产摄影运镜模式库/AI执行/方法库.json`。原有两套库仅作为来源，引用而不复制、不搬动、不覆盖 AST 原片。运行证据独立写到 `04_测试与验收/方法库实测/`；本目录只保存执行和校验程序，不创建 Pi 扩展或全量视频台本。

## 状态合同

- `capture`：本房源单动作 VR 采集；`post`：已有实测素材的后期；`narrative`：文案与画面配对规则。
- 每项独立保留 `policy`（default / optional / prohibited）及 `verification`（pending / passed / blocked）。技术可运行不等于推荐。
- 正式使用门禁：技术 passed、视觉核对 accept、policy 非 prohibited、有证据与兼容当前房源。AI 不得从旧 README 中的“100%通过”推导许可。
- 配置中的路径相对当前项目根；画廊由索引生成。静态资产来源只读，证据追加写入新 take 目录，拒绝覆盖。
- 房产事实仅引用 `02_架构与合同/01_房产核心档案.md`，不要从模式名称推断存在家具、床的尺寸或客餐厅的精确长轴米数。

## 关键取舍

1. 将“穿门推进”与“穿门转场”合为一个方法，两个旧名称均保留 alias；娃娃屋方法合并两个来源，“碎片破面”保留为不同的后期特效，禁止混用。
2. FOV 微推不是 dolly；它不改变机位坐标。环绕需要多点几何与防碰撞实测，不能从横摇示例自动推导；尚不提供可拍 orbit 路线。
3. 慢摇用平滑缓动，不沿用旧模板 0.6 rad/s 的大幅快扫。75–85°为本项目默认 FOV；历史 90–95°保留为历史素材参数，不能覆盖冻结合同。
4. 用户已明确批准本房源 VR 录屏使用扫描原生高度的例外（相机/standingPosition 约1.17m）；真人拍摄仍为1.5–1.6m。不伪造全景相机平移来凑高度。三维俯视为单独的示意视角，不得冒充真实看房行走。
5. 邻接表仅证明可达，不证明沿程离墙0.5m。未取得可靠碰撞距离时写 `metric_clearance=unverified`，依靠已检查的接触表/短转场逐帧表与固定点位降级；视觉采样不等于逐帧人工观看，更不认证米级净空。
6. 使用现成 agent-browser、ffmpeg、Five SDK 与本目录的单项接收器；npm检索未找到本房源点位方法配置的直接替代包，不新增Pi工具。Computer Use 当前签名校验失败，浏览器 UI 操作与 SDK 验证分别记录，绝不冒充桌面服务测试。

## 单项闭环

读取一项配置 → 校验房源/机位/邻接/禁用策略 → 预加载 → 单动作录制 → 遥测/视频/起中末帧落盘 → 接触表/必要逐帧表视觉核对 → 记录 accept 或 reject → 才能定义下一项待拍动作。

配置可以索引所有方法，但不包含整片脚本。`take.js` 每次只接受一个 recipe，不提供批量整片执行入口。后期方法必须引用已通过核对的采集片段。

## 后续入口

具体命令、降级方式和复验规则见资产库的 `AI执行/README.md`。运行记录不得覆盖原片；输出模式、时长、点位终态、视频有效性必须分别验证。

后续修复入口`repair.py`每次只执行一个安全变体；已新增并接受P03V1/P05V1/P06V1/P07V1/P08V1/P09V1。原禁用/拒绝记录不解禁，P10按用户“暂不付费”决定延期（P10-decision-01.json），本次不得调用。最新修复证据`acceptance-repair-02.json`含23项测试、391个哈希、34条视频全帧解码；六项安全变体已交付，不宣称七项原效果全部通过。

初次完成25项的验收或受限处置：18项配方可复用，3项后期视觉拒绝，4项blocked未执行。`verify.py`提供只读复验（含门禁、哈希、全帧解码和终态）；证据见`04_测试与验收/方法库实测/acceptance-01.json`。`点位.json`的27点归属来自当前SDK，只有配方涉及的6点具有本轮视觉凭据。
