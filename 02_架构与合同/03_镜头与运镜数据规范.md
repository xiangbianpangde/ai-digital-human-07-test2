# 摄像机运镜与数据规范合同 (Camera Path Contract)

> 规范摄像机镜头轨迹、空间热点定位、运镜转场与防穿模规则。支撑后续第3、4、5阶段的自动化脚本与 Computer Use 测试。

---

## 1. 镜头设计原则 (基于参考视频与运镜参考图)

参考图 (`05_资产库/03_参考示例/camera_path_reference_example.png`) 与标杆视频实践，确立四大核心准则：

1. **覆盖所有关键区域**：
   - 避免仅单一视角，必须覆盖：客餐厅大视角 -> 南阳台远眺 -> 环顾客餐厅 -> 过道枢纽 -> 豪华主卧套房 -> 北向功能房。
2. **合理的过渡与转场**：
   - 相邻镜头必须遵循空间连续性，不出现空间瞬移造成的认知割裂；
   - 运动镜头推进时保持平稳匀速，避免快速摇晃导致观众眩晕。
3. **严格不穿模、视角合理**：
   - 摄像机高度统一维持在成人视线高度（约 1.5m ~ 1.6m）；
   - 镜头避开门框边缘、墙体转角与高大家具，保留至少 0.5m 安全防撞冗余；
   - 视场角（FOV）建议维持在 75° ~ 85° 广角透视，既显空间开阔又不变形。
4. **支持分段测试与人工介入微调**：
   - 严格落实**边写脚本边测试**（第5条铁律），每个分镜规划后立即通过贝壳漫游或 Computer Use 运行验证，通过后再推进下一镜。

## 2. 空间点位编码规则 (Camera Waypoints)

| 点位编号 | 所在空间 | 建议视角朝向 (Yaw/Pitch) | 镜头运动意图 |
|---|---|---|---|
| `WP_01_FOYER` | 入户玄关/客餐厅衔接处 | 面向客厅全景 (西南) | **建立空间第一印象**：推镜进入，展现31㎡大横厅 |
| `WP_02_LIVING` | 客厅中央 | 视线投向南向大阳台 (南) | **推向卖点**：从沙发区平滑推向阳台与落地窗景 |
| `WP_03_BALCONY_A`| 阳台A前沿 | 转身 180° 回望客餐厅 (东北) | **空间尺度回望**：站在阳台感受客餐厅纵深与大平层开阔感 |
| `WP_04_HALLWAY` | 过道入口 | 沿过道向前推进 (东) | **空间转场动线**：从动区穿入静区，展示动静分区 |
| `WP_05_BED_B_ENTRY`| 主卧套房门口 | 面向主卧大床及南向窗 (东南) | **进入私密奢享**：展示24㎡主卧套间宽敞尺度 |
| `WP_06_BED_B_WINDOW`| 主卧窗边 | 回顾衣帽间与主卫过渡口 | **套房细节补证**：突出步入式衣帽间与主卫配套 |
| `WP_07_BED_D` | 卧室D/书房 | 面向北向窗及生活阳台 (北) | **功能拓展展示**：展示北向双阳台对流与书房布局 |

## 3. 运镜数据结构 (JSON Schema 规范)

后续在 `03_实现/` 和 `09_提案与草稿/` 中编写的镜头路径文件需遵循以下 JSON 结构：

```json
{
  "$schema": "https://json-schema.org/camera-path/v1.json",
  "shot_id": "SHOT-01",
  "name": "客厅全景推进至阳台",
  "start_waypoint": "WP_01_FOYER",
  "end_waypoint": "WP_02_LIVING",
  "duration_sec": 4.5,
  "camera_motion": {
    "type": "dolly_in", // dolly_in, pan, tilt, static, orbit
    "speed": "smooth_slow",
    "collision_check": "passed",
    "fov_deg": 80
  },
  "narration_cue": "走进沙湖九号，映入眼帘的是这间超过30平的奢阔大横厅……",
  "test_status": "pending_test" // pending_test, passed, blocked
}
```

## 4. 自动化驱动与可行性验证门禁

在 Stage 4/5 阶段：
- **可行性门禁**：通过贝壳 VR 网页的键盘/鼠标/Canvas 事件或 Computer Use 模拟点击地面漫游点；
- **防卡死检测**：如果某节点无法平滑转动或被遮挡，必须降级为定点平滑摇镜（Pan）或调整为邻近热点。
